1. SYSTEM OVERVIEW & FRONTEND TECH STACK
====================================================================================================
HabeshaFreight Frontend is a modern, responsive Single Page Application (SPA) built to deliver 
a role-tailored digital workspace for Shippers, Drivers, Fleet Owners, and Platform Administrators. 
It features role-specific navigation layouts, interactive dashboards, real-time spatial tracking 
views, payment escrow modally-driven workflows, and comprehensive verification queues.

Core Frontend Technical Stack:
- Core Framework: React 18.3.1
- Build Tool & Dev Server: Vite 5.4.1 (ES Modules build optimization)
- Programming Language: TypeScript 5.5.3 (Strict Type Safety & Interface Contracts)
- Routing Engine: React Router DOM 6.26.2 (Browser Router with Splat & Transition Flags)
- Styling & UI Engine: Tailwind CSS 3.4.19 with PostCSS & Autoprefixer
- State Management: React Context API (`AuthContext`, `ThemeContext`)
- HTTP & API Client: Axios 1.19.0 (Custom instance with Request/Response Interceptors)
- Iconography & UI Assets: Lucide React (Modular SVG Icons)
- Containerization & Production Web Server: Docker & Nginx (Multi-Stage Build Pipeline)

3. COMPONENT & PAGE SYSTEM BREAKDOWN
====================================================================================================

1. Shipper Portal Modules (`/pages/shipper/*`):
   - `ShipperHome`: Landing page featuring value propositions, regional route coverage, and quick login/register links.
   - `ShipperDashboard`: Command center displaying cargo statistics (Total, Active, Completed, Pending Bids, Total Spend).
   - `ShipperCreateShipment`: Multi-step form capturing cargo description, weight in tons, origin/destination cities, GPS coordinates, and initial offered price in ETB.
   - `ShipperBids`: Real-time view of driver offers submitted for posted loads. Displays driver rating, past completed trips, offered price, and vehicle capacity checks. Contains action buttons for Accepting or Rejecting bids.
   - `ShipperPayments`: Displays locked escrow funds, gateway references, and provides deposit action buttons for Telebirr and Chapa payments.
   - `ShipperTracking`: Interactive map view tracking assigned driver location coordinates in real-time.

2. Driver Portal Modules (`/pages/driver/*`):
   - `DriverDashboard`: Mobile-optimized driver view summarizing current trip status, wallet balance, active bids, and quick navigation.
   - `AvailableLoads`: Spatial cargo search displaying loads filtered by origin city, destination, and distance radius.
   - `SubmitBid`: Modal/page allowing drivers to select an active verified vehicle from their fleet, enter a competitive price bid in ETB, and submit.
   - `ActiveDelivery`: High-priority operational view for active trips. Contains input fields for Pickup OTP (at cargo collection) and Delivery OTP (at cargo delivery).
   - `DriverWallet`: Financial balance view breaking down gross earnings, platform commission (5%), locked escrow, and released payout funds.

3. Transport Company (Fleet Owner) Modules (`/pages/company/*`):
   - `CompanyDashboard`: Executive metrics for fleet operators (Total Vehicles, Active Drivers, Total Fleet Revenue).
   - `CompanyVehicles`: Inventory management interface for adding trucks, entering license plate numbers, capacity in tons, vehicle type ('ISUZU', 'SINO_TRUCK', 'TRAILER', 'PICKUP'), and tracking verification state.
   - `CompanyDrivers`: Directory for attaching drivers to company fleet assets.

4. Admin Operations Suite Modules (`/pages/admin/*`):
   - `AdminDashboard`: Platform governance suite showing system health indicators, user growth, revenue metrics, and system activity logs.
   - `AdminVerification`: KYC Queue displaying driver license photos and fleet owner registration certificates for verification. Features Approve and Reject controls.
   - `AdminDisputes`: Arbitration board for open disputes. Admins view dispute category ('DAMAGE', 'DELAY', 'PAYMENT', 'OTHER'), review claims, enter resolution notes, and trigger either `REFUND_SHIPPER` or `RELEASE_CARRIER`.
   - `AdminAuditLogs`: Detailed search and filter view for inspecting security audit events.

4. FRONTEND SECURITY PROTOCOLS & IMPLEMENTATION DETAILS
====================================================================================================
The frontend application implements strict security controls to protect client sessions, 
enforce role separation, and prevent unauthorized state access:

1. JWT Bearer Interception & LocalStorage Storage:
   - Upon successful login or OTP verification, the backend JWT token is stored in `localStorage` under `hf_token`.
   - The central Axios client (`axiosInstance` in `services/api.ts`) configures a request interceptor:
     ```typescript
     axiosInstance.interceptors.request.use((config) => {
       const token = localStorage.getItem('hf_token');
       if (token) {
         config.headers['Authorization'] = `Bearer ${token}`;
       }
       return config;
     });
     ```
   - Every outgoing API call automatically attaches the Bearer token without manual code replication.

2. Client-Side Role-Based Access Control (RBAC):
   - Enforced by `ProtectedRoute.tsx`.
   - Before rendering any route, `ProtectedRoute` inspects the active user role from `AuthContext`:
     * If unauthenticated -> Redirects to `/login`.
     * If user role does NOT match `allowedRoles` -> Automatically redirects user to their designated home route:
       - `DRIVER` -> `/driver`
       - `FLEET_OWNER` -> `/company`
       - `ADMIN` -> `/admin`
       - `SHIPPER` -> `/dashboard`

3. Identity & KYC Verification Routing Guards:
   - For users with role `DRIVER` or `FLEET_OWNER`, `ProtectedRoute` evaluates `kyc_status`.
   - If `kyc_status === 'PENDING'`, the user is restricted from accessing operational pages and automatically redirected to `/pending-approval`.
   - Access to bidding and active delivery features is blocked until an Administrator approves their identity documents.

4. Form Input Validation & File Upload Security:
   - Form fields undergo client-side validation (email format, phone number regex, non-negative numbers for prices/weight).
   - Document uploads (Driver License / Company Registration) use `FileService` client checks to restrict files to image/PDF formats with a maximum file size limit (10MB).
   - Multi-part requests are submitted via `FormData` payloads.

5. Automatic Session Invalidation & Error Interception:
   - The Axios response interceptor captures HTTP `401 Unauthorized` or `TOKEN_EXPIRED` errors.
   - On expiration, the client automatically clears `hf_token` and `hf_user` from `localStorage` and resets `AuthContext` state, redirecting the user safely to `/login`.

5. STATE MANAGEMENT & API SERVICE LAYER
====================================================================================================
State management relies on a clean, centralized React Context Architecture paired with modular 
API service wrappers:

1. Context State Providers:
   - `AuthContext`: Manages current `user` object, `token` string, `isLoading` state, `login()`, `register()`, `verifyOtp()`, and `logout()` actions.
   - `ThemeContext`: Toggles application-wide Light/Dark themes and persists selection in `localStorage`.

2. Service Layer Wrappers:
   - `services/api.ts`: Exports unwrapped helper methods (`get`, `post`, `put`, `patch`, `del`) that parse standardized backend envelopes (`{ success, message, data }`) and return clean payload data directly.
   - `services/authService.ts`: Abstracts token retrieval, session storage, and current user profile fetching (`GET /api/auth/me`).
   - `services/adminApi.ts`: Type-safe client method collection covering all 32 Admin REST endpoints.

                                                    |
[User]    --(Navigates to OTP Verification)--> [VerifyOTP.tsx (/verify-otp)]
                                                    |
                                         (Inputs 6-Digit OTP Code)
                                         [POST /api/auth/verify-otp]
                                                    |
                         +--------------------------+--------------------------+
                         |                                                     |
                 [Role == SHIPPER]                                    [Role == DRIVER / FLEET_OWNER]
                         |                                                     |
             (Navigates to Dashboard)                                (kyc_status == PENDING)
             [ShipperDashboard (/dashboard)]                                   |
                                                                  (ProtectedRoute Redirects)
                                                                               |
                                                                    [PendingApproval.tsx]
                                                               (Awaits Admin KYC Approval)


Flow 2: Shipper Load Creation, Bidding Management & Escrow Payment
----------------------------------------------------------------------------------------------------
[Shipper] --(Navigates to Create Load)---> [ShipperCreateShipment.tsx (/shipments/create)]
                                                    |
                                    (Inputs Origin, Destination, Weight, Price)
                                    [POST /api/loads]
                                                    |
[Shipper] --(Navigates to Bids View)-----> [ShipperBids.tsx (/bids)]
                                                    |
                                    (Reviews incoming Driver Bids)

                                    (Selects Verified Vehicle & Offers Price)

                                                    |
             ... Wait for Shipper Acceptance ...
                                                    |

                                                    |

7. PRODUCTION BUILD & DEPLOYMENT CONFIGURATION
====================================================================================================
The frontend is configured for production deployment using Vite bundler and containerized Nginx:

1. Build & Compilation (`npm run build`):
   - TypeScript compiler type-checks the entire codebase (`tsc`).
   - Vite compiles React components, optimizes assets, tree-shakes unused dependencies, and outputs minified static assets to the `dist/` directory.

2. Production Containerization (`Dockerfile`):
   - Stage 1 (Build): Uses Node.js 20 container to install dependencies and run `npm run build`.
   - Stage 2 (Serve): Copies compiled `dist/` static files to lightweight Nginx Alpine container.
   - Nginx Routing Configuration (`nginx.conf`): Serves `index.html` for all client-side routes, enabling smooth HTML5 React Router single-page navigation without 404 server errors.
